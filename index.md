# GNOME Widget Panel index

Configurable floating GNOME Shell panel implemented as TypeScript source and
generated GJS runtime code.

## Directories

- [`extension-src/`](extension-src/) — source of truth for TypeScript modules,
  static GNOME extension assets and plugin-local documentation.
- `extension/` — generated install tree produced by `npm run build`; a build
  artifact (gitignored, not committed), regenerated wholesale on every build. Do
  not edit it directly.
- [`extension-src/plugins/`](extension-src/plugins/index.md) — built-in widget
  plugins, one directory per widget.
- [`docs/`](docs/index.md) — **all** documentation, split by category:
  [`specification/`](docs/specification/index.md) (user-visible behaviour),
  [`implementation/`](docs/implementation/index.md) (internals),
  [`testing/`](docs/testing/index.md) (test cases and harnesses),
  [`process/`](docs/process/index.md) (workflow, release, bug and quality rules),
  [`roadmap/`](docs/roadmap/index.md) (planned, not built),
  [`requests/`](docs/requests/index.md) (per-task working files) and the
  [tag registry](docs/tags.md).
- [`schema/`](schema/) — JSON schemas for future external widget manifests.
- `.claude/rules/llm-wiki-tags/` — the documentation and tagging rules Claude
  Code loads on every task; summarised in [`AGENTS.md`](AGENTS.md) for other
  agents.
- [`tests/`](tests/index.md) — Node unit tests for the gi-free pure-logic
  modules (`npm test`) and the headless GNOME Shell UI regression suite
  (`npm run test:ui`, [`tests/ui/`](tests/ui/index.md)).

## Main files

The repository root is kept minimal: this index, the agent/user entry documents,
the licence, the build and install entry-point scripts, and the files tooling
requires there. Everything else is documentation and lives under `docs/` — see
the "Documentation: llm-wiki-tags" section in [`AGENTS.md`](AGENTS.md).

- [`AGENTS.md`](AGENTS.md) — working rules, including where each kind of
  document belongs and the LLM-wiki/tag conventions.
- [`README.md`](README.md) — user-facing overview, install and development
  commands.
- [`docs/roadmap/backlog.md`](docs/roadmap/backlog.md) — contract-typing backlog, panel roadmap and the
  requested-features backlog (new widgets and per-widget settings work).
- `.github/ISSUE_TEMPLATE/` — GitHub issue *forms* (`bug_report.yml`,
  `feature_request.yml`, `widget_request.yml`, `config.yml`) opened prefilled
  from the extension's About page and Add-a-widget subpage via
  `extension-src/systemInfo.ts`.
- [`.github/workflows/`](.github/workflows/index.md) — CI (build/type-check/test)
  and Release (bump, pack, GitHub Release, extensions.gnome.org upload) GitHub
  Actions and their `.github/scripts/` helpers; see
  [`docs/process/release.md`](docs/process/release.md).
- `CHANGELOG.md` — generated overview of every release with a GNOME Shell
  version → plugin version support matrix (regenerated by the Release workflow
  from [`docs/process/releases.json`](docs/process/releases.json); see
  [`docs/process/release.md`](docs/process/release.md)).
- [`build.sh`](build.sh) — regenerates `extension/` from `extension-src/`;
  after `tsc` it runs [`tools/format-generated.mjs`](tools/index.md) to reinsert
  the readable blank-line spacing `tsc` strips from the emitted JS.
- [`tools/`](tools/index.md) — build/developer tooling (generated-JS formatter,
  dev screenshot helper).
- [`install.sh`](install.sh) — builds and installs the extension into the user
  GNOME Shell extension directory.
- [`dev-install.sh`](dev-install.sh) — symlink developer install for reload
  without logout.
- [`dev-run.sh`](dev-run.sh) — rebuild and run a restartable nested GNOME Shell
  window (`gnome-shell --devkit`), tailing the extension log.
- [`dev-gsettings-diagnose.sh`](dev-gsettings-diagnose.sh) — inspect and poke
  the dev-shell GSettings/dconf profile used by `dev-run.sh`.
- [`docs/implementation/object-model.md`](docs/implementation/object-model.md) — runtime object map.
- [`docs/implementation/architecture.md`](docs/implementation/architecture.md) — architecture and roadmap.
- [`docs/process/development.md`](docs/process/development.md) — reload-without-logout workflow.

## Development path

Edit TypeScript in `extension-src/`, run `npm run build`, then run
`./install.sh` (needs logout/login on Wayland). For fast iteration without
logout, use `./dev-install.sh` once and `./dev-run.sh` to reload in a nested
GNOME Shell; see [`docs/process/development.md`](docs/process/development.md).
